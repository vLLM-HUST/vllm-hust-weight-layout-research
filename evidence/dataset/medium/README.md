# Medium 正式版

仅使用原 MMLU-Pro 数据，继承冻结的 Large 请求内容与 ID。

性能：P1（512/128）、P2（1024/1024）、P3（8192/256）、P4（32768/256）、P5（131072/256），括号为输入/输出 tokens；每档 64 条，共 320 条，为 Large 1280 条的 25%。采用原 Large 各档固定提交顺序前 64 条。

质量：2,406 题，为 Large 12,032 题的约 20%。Hamilton 最大余数法分配学科比例，学科内部用 seed 与题目 ID 的 SHA256 排序选择。答案独立存储，保持原正常 EOS 和严格单字母判分规则。

正式性能并发：1/4/8/16/32/64。每档 64 条请求能达到并发 64，但不足以声称长时间持续满载。服务端总序列预算仍为 64。高并发短批存在收尾效应，使用相同请求与并发作方案对照；长时吞吐另用 15 分钟稳定性测试。

数据文件与 ID 清单见 manifest.json；原 Small/Large 文件及其 manifest 不修改。已完成 Large 的质量输出可按 ID 复用；Large 吞吐保留原规模标签，不能冒充 Medium 吞吐，也不参与 Medium 三轮吞吐均值。
